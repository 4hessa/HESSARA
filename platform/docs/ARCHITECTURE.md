# البنية وخريطة الصفحات

## خريطة الصفحات

| المسار | الوصول | الوظيفة |
|---|---|---|
| `/` | الزائر (المسجَّل يُحوَّل إلى `/home`) | الصفحة التعريفية: القيمة، الخطوات، النماذج، الوكلاء، مثال المختبر، معاينة حية، الميديا |
| `/login` (+ `?mode=signup`) | الزائر | دخول وإنشاء حساب |
| `/home` | مسجَّل | لوحة العمل: حقل الاستشارة، مهام البدء، آخر الاستشارات، المحفوظات، المفضلات |
| `/consult` | مسجَّل | السجل والبحث وبدء استشارة |
| `/consult/new` | مسجَّل | استشارة جديدة؛ مع `?agent=` نموذج الإدخال المنظّم للوكيل |
| `/consult/[id]` | صاحبها فقط | مساحة المحادثة + لوحة المراجعة |
| `/models` `/agents` `/media` | الجميع | الاكتشاف والاختيار |
| `/lab` | مسجَّل | مختبر النقد والتقييم |
| `/profile` | مسجَّل | الهوية، التفضيلات، التذكير، الخصوصية، حذف الحساب |
| `/help` `/privacy` `/terms` | الجميع | المساعدة والسياسات |

## رحلة الاستخدام الرئيسية

```
الزائر يكتب مشكلته في /
   └─ يُحفظ النص في sessionStorage (بإفصاح ظاهر) ← /login?next=/consult/new
        └─ إنشاء حساب ← /consult/new (النص مستعاد)
             └─ إرسال ← POST /api/consultations ← /consult/[id]
                  └─ بثّ الإجابة (NDJSON) مع اسم النموذج على كل رسالة
                       ├─ «مراجعة نقدية» ← POST /api/reviews ← ملاحظات وفق معايير معلنة
                       ├─ حفظ الاستشارة ← PATCH saved
                       └─ «اجعله نموذجي المفضل» ← PATCH /api/me ← يظهر في الشريط العلوي
العودة ← /home: الاسم + النموذج المفضل + الاستشارة السابقة
```

## الطبقات

| الطبقة | الموضع | المسؤولية |
|---|---|---|
| العرض | `app/`, `components/` | صفحات خادم تقرأ البيانات مباشرة؛ مكونات عميل للتفاعل |
| التطبيق | `app/api/` | المصادقة، التحقق من المدخلات والملكية، حدود المعدل |
| توجيه النماذج | `lib/providers/` | عقد `ProviderAdapter.stream()` واحد؛ موائم لكل مزوّد؛ حساب الحالة الفعلية |
| الوكلاء | `lib/catalog/agents.ts`, `lib/consult.ts` | تعليمات + نموذج إدخال + عقد مخرجات + نمط مراجعة افتراضي |
| التقييم | `lib/review/` | أنماط ومعايير، مراجع قاعدي، مراجع لغوي بمخرجات JSON، أداة المقارنة |
| البيانات | `lib/db.ts` | SQLite أو PostgreSQL: users, sessions, consultations, messages, reviews, favorites, actions |

## قرارات تقنية ومبرراتها

1. **المستودع كان فارغًا** (ملف README من سطر واحد)، فلم يكن هناك إطار قائم للحفاظ عليه. اختير Next.js لأنه يجمع العرض والواجهة البرمجية في مشروع واحد قابل للنشر، مع TypeScript.
2. **CSS عادي برموز تصميم** بدل مكتبة واجهات: نظام التصميم مخصّص، وعدد الاعتماديات أقل (أربع حزم تشغيلية: next، react، react-dom، وحزمة Anthropic).
3. **طبقة بيانات بثلاثة محركات خلف واجهة واحدة** (`all`, `get`, `run` غير متزامنة): `node:sqlite` المضمّنة محليًا (صفر إعداد)، و PostgreSQL عند ضبط `DATABASE_URL` للاستضافة عديمة الحالة، و PGlite للاختبار الآلي لمسار Postgres. الاستعلامات مكتوبة بمجموعة SQL مشتركة، والاختبار الشامل يُشغَّل على المحركين (`npm run e2e` و `E2E_DB=pglite npm run e2e`).
4. **مصادقة مكتوبة يدويًا** (scrypt + جلسات في القاعدة) بدل خدمة خارجية: لا اعتماد على طرف ثالث، والسلوك كله قابل للشرح أمام اللجنة.
5. **موائمات المزوّدين**: Anthropic عبر الحزمة الرسمية؛ البقية عبر HTTP مباشر لتفادي حزمة لكل مزوّد. تغيير المزوّد لا يمسّ الواجهة.
6. **المحرك التجريبي والمراجع القاعدي** وُجدا لإثبات المسار دون مفاتيح، ويُوسَمان في كل موضع بأنهما ليسا ذكاءً اصطناعيًا.
7. **معرّفات إصدارات النماذج غير Anthropic تُقرأ من متغيرات البيئة** ولا تُكتب في الشفرة: لم يمكن التحقق من الإصدارات الحالية لتلك المزوّدات من بيئة البناء.
8. **بروتوكول البث NDJSON** فوق `fetch`: يدعم الإلغاء (`AbortController`) وحفظ الإجابة الجزئية بحالة «غير مكتملة».

## تعريف الوكيل

الوكيل ليس اسمًا فوق نموذج محادثة. يختلف عن الاستشارة العامة في أربعة أمور قابلة للفحص في الشفرة:
تعليمات تخصصية تُضاف لتعليمات النظام، نموذج إدخال منظّم بحقول خاصة بمجاله، عقد مخرجات (عناوين الإجابة)، ونمط مراجعة افتراضي في لوحة النقد.
**لا أدوات خارجية** في هذه النسخة؛ سجل الإجراءات يسجّل استدعاءات النماذج والمراجعات الفعلية فقط.
