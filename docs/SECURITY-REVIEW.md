# المراجعة الأمنية

التاريخ: ٢٠٢٦-١١-١١، وأُضيفت مراجعة مستقلة في ٢٠٢٦-١١-١٢ (القسم الأخير). المنهج: [cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill)
(الملف الرئيسي وملفات: المصادقة وبروتوكول الويب، الذكاء الاصطناعي، عزل البيانات، استنزاف الموارد).

## النطاق والحدود — يُقرأ أولًا

- هذه **مراجعة مركّزة للمصدر (وضع الإرشاد في المهارة) وليست التدقيق الكامل ذي المراحل الست**.
  التدقيق الكامل يشترط وكلاء منفصلين للاستطلاع والصيد والتحقق المستقل وسجل تغطية؛ لم يُنفَّذ ذلك.
- الجولة الأولى أجراها كاتب الشفرة نفسه. أُضيفت بعدها **مراجعة مستقلة واحدة** بوكيل لم يكتب الشفرة (قراءة مصدر فقط)، ووجدت ما فات الجولة الأولى. هذا ما زال دون التدقيق الكامل: مراجع واحد لا موجات صيد وتحقق متعددة.
- التغطية جزئية: لا يصح الاستنتاج أن ما لم يُذكر هنا سليم.
- لم يُفحص: إعدادات النشر والوسيط العكسي و TLS (خارج المستودع)، سلسلة توريد الاعتماديات (سوى `npm audit` عند التثبيت: صفر ثغرات معروفة)، موائمات المزوّدين أمام خوادم حقيقية.
- الأدلة: قراءة المصدر + اختبارات محلية على خادم مؤقت بحسابات وهمية (`scripts/e2e.mjs`).

## الحدود الأمنية للنظام

| الطرف الأقل ثقة | الحد | المورد المحمي |
|---|---|---|
| زائر غير مسجَّل | المصادقة | بيانات الحسابات، موارد الخادم |
| مستخدم مسجَّل | الملكية (`user_id`) | استشارات ومراجعات ومفضلات غيره |
| موقع آخر في متصفح الضحية | فحص الأصل + `SameSite` | إجراءات الضحية |
| نص ملصق / مخرجات نموذج | العرض الآمن، فصل البيانات عن التعليمات | متصفح المستخدم، تعليمات النظام |
| المتصفح | الخادم | مفاتيح المزوّدين |

## ما وُجد وأُصلح

الخطورة وفق مقياس المهارة، وبحسب الأثر المُثبَت فقط.

### ١. استنزاف ذاكرة في أداة المقارنة — متوسطة — أُصلح
- **المسار**: مستخدم مسجَّل (التسجيل مفتوح) ← `POST /api/reviews` بنص من آلاف الأسطر القصيرة ← `POST /api/reviews/[id]/revise` بنسخة مماثلة ← `diffWords`.
- **الخلل**: عند تجاوز حد الكلمات كانت الدالة تنتقل إلى مقارنة الأسطر **دون حد**: عشرة آلاف سطر × عشرة آلاف = مئة مليون خانة ≈ 400 ميغابايت، محسوبة تزامنيًا على حلقة الأحداث.
- **الأثر**: مستخدم واحد يعطّل الخادم لكل المستخدمين (عملية واحدة).
- **الإصلاح**: سقف صارم لعدد الخانات (`MAX_CELLS`) مع مخرج خشن عند تجاوزه. `lib/review/diff.ts`.
- **الدليل**: اختبار وحدة (زمن < 500 مللي ثانية، ذاكرة < 50 ميغابايت) + فحص شامل عبر الواجهة البرمجية.

### ٢. قراءة جسم الطلب دون حد قبل المصادقة — متوسطة — أُصلح
- **المسار**: أي زائر ← `POST` إلى الدخول أو التسجيل أو المعاينة بجسم ضخم.
- **الخلل**: `readJson` كانت تقرأ الجسم كاملًا في الذاكرة ثم تفحص طوله.
- **الإصلاح**: رفض بحسب `Content-Length`، ثم قراءة متدفقة تتوقف عند الحد. `lib/http.ts`.
- **الدليل**: فحص شامل بجسم 300 كيلوبايت.
- **يحتاج تحققًا**: هل يفرض الوسيط العكسي في النشر حدًّا أبكر؟ خارج المستودع.

### ٣. تحديد المعدل مبني على ترويسة يكتبها العميل — متوسطة — أُصلح على مرحلتين
- **الخلل الأصلي**: مفتاح الحد كان `X-Forwarded-For` كما يرسلها العميل؛ تدويرها يتجاوز حد محاولات الدخول.
- **الإصلاح الأول كان معيبًا**: استبدلتُ به حدًّا إجماليًا للخادم عند غياب وسيط موثوق. المراجعة المستقلة بيّنت أن هذا يمكّن زائرًا واحدًا من قفل الدخول والتسجيل على الجميع بنحو طلب كل ثانيتين (انظر م١ أدناه).
- **الإصلاح الحالي**: عدّاد **إخفاقات** لكل بريد (يزيد عند الفشل فقط ويُصفَّر عند النجاح)؛ حد العنوان يعمل فقط مع `HESSARA_TRUST_PROXY=1`؛ لا حد إجمالي مشترك. `lib/http.ts`، `app/api/auth/login/route.ts`.
- **مقايضة باقية ومعلنة**: عشر محاولات فاشلة على بريد معروف تمنع صاحبه من الدخول ربع ساعة. ودون وسيط موثوق لا يوجد حد على معدل التسجيل.

### ٤. تجزئة كلمة المرور تحجب حلقة الأحداث — منخفضة — أُصلح
- `scryptSync` استُبدلت بالنسخة غير المتزامنة. `lib/auth.ts`.

### ٥. فرق زمني يكشف وجود الحساب عند الدخول — منخفضة — أُصلح
- عند غياب البريد كان الرد أسرع (لا تجزئة). تُحسب الآن تجزئة وهمية. `lib/auth.ts`.

### ٦. تسريب محتمل لنص خطأ داخلي في نتيجة المراجعة — معلوماتية — أُصلح
- رسالة الاستثناء غير المصنّف كانت تُدرج في «حدود المراجعة». تُعرض الآن رسالة عامة. `lib/review/index.ts`.

### ٧. لا سقف زمني لاستدعاء المزوّد — تقوية — أُضيف
- خمس دقائق للتوليد ودقيقتان للمراجعة.

## ما فُحص ولم يُوجد فيه خلل

| الصنف | النتيجة | الدليل |
|---|---|---|
| الوصول إلى موارد الغير (IDOR) | كل استعلام يشترط `user_id`؛ الصفحة والواجهة والتصدير تعيد 404 لغير المالك | مصدر + ثلاثة فحوص شاملة |
| حقن SQL | استعلامات مُعدّة حصرًا؛ أسماء الأعمدة في `PATCH /api/me` ثابتة؛ `LIKE` مع تهريب | مصدر |
| XSS المخزَّن ومخرجات النماذج | عارض Markdown يبني عناصر React دون HTML خام؛ الروابط `http(s)` فقط مع `noopener` | مصدر + فحص شامل |
| CSRF | رفض الأصل المخالف لكل طلب مغيِّر + `SameSite=Lax` | مصدر + فحص شامل |
| تثبيت الجلسة وإبطالها | رمز جديد عند كل دخول؛ الخروج وحذف الحساب يحذفان الجلسات؛ الرمز مخزَّن مجزّأً | مصدر + فحص شامل |
| إعادة التوجيه المفتوحة | `next` يقبل مسارًا داخليًا فقط | مصدر + فحص شامل |
| كشف الأسرار للمتصفح | المفاتيح تُقرأ في الخادم فقط؛ الحزمة لا تحوي أسماءها ولا تعليمات النظام | فحص شامل للحزمة |
| حقن التعليمات | النص الملصق موسوم بيانات؛ لا أدوات ولا سياق مشترك بين المستخدمين، فأقصى أثر يقع على محادثة صاحبه نفسه | مصدر |
| دورة حياة البيانات | الحذف فعلي متتابع (لا حذف ناعم)، ولا مهام خلفية تعيد إنشاء البيانات | مصدر + فحص شامل |

## ملاحظات تقوية (ليست ثغرات مثبتة)

- سياسة أمان المحتوى تسمح بـ `'unsafe-inline'` للسكربتات (يتطلبها الإطار دون nonce). تضعف الدفاع في العمق ضد XSS؛ لا مسار حقن معروف حاليًا.
- التسجيل يفصح عن وجود البريد («يوجد حساب»). مقايضة شائعة لصالح الوضوح.
- لا حد لعدد الاستشارات أو حجم التخزين لكل مستخدم سوى حدود المعدل.
- لا تأكيد للبريد ولا تغيير لكلمة المرور ولا مصادقة ثنائية.
- حدود المعدل في ذاكرة عملية واحدة: تُصفَّر عند إعادة التشغيل ولا تُشارَك بين النسخ.
- ترويسة `x-forwarded-host` تُعتمد في فحص الأصل؛ آمن خلف وسيط يعيد كتابتها — **يحتاج تحققًا** عند النشر.

## المراجعة المستقلة (٢٠٢٦-١١-١٢)

مراجع لم يكتب الشفرة قرأ `lib/` وكل مسارات `app/api/` وملفات العرض الحساسة، ثم قارن بتقرير الجولة الأولى.
**لم يجد**: وصولًا لبيانات الغير، حقن SQL، منفذ XSS، إعادة توجيه مفتوحة، أو تسريب مفاتيح. كل ما أكّده يخص التوافر والحصص.

تحقُّق المراجع من الإصلاحات السبعة الأولى: خمسة «موجودة وفعّالة»، واثنان «موجودان وناقصان» (البند ٣ والسقف الزمني) وقد استُكملا أعلاه.

### يحتاج تحققًا عند النشر (خارج المستودع)
- هل يوجد وسيط موثوق واحد يضيف عنوان العميل؟ مع شبكة توزيع أمام الوسيط يصير «آخر عنوان» عنوان الشبكة لا العميل.
- هل يضبط الوسيط `X-Forwarded-Host` أو يحفظ `Host`؟ وإلا رُفضت كل الطلبات المغيِّرة.
- هل يصل انقطاع العميل إلى الخادم خلف الوسيط؟ وإلا استمر التوليد المتروك حتى السقف الزمني.
- ألا يُضبط `HESSARA_INSECURE_COOKIE` في الإنتاج.

### ما لم تغطّه المراجعة المستقلة
لا اختبار ديناميكي ولا قياس زمن؛ الاعتماديات وسلسلة التوريد؛ إعدادات النشر؛ مكونات العرض غير المذكورة فُحصت بحثًا عن المنافذ فقط.

## الخطوة التالية الموصى بها

تشغيل التدقيق الكامل للمهارة (بوكلاء مستقلين) قبل أي نشر عام، ومراجعة إعدادات النشر الفعلية.
